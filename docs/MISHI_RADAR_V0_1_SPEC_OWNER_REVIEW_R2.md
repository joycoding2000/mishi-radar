## 1. 商业目标及产品质量底线

Mishi Radar 是面向有 A 股交易经验、不会编程的个人投资者的**可购买、可试用、可持续使用的成熟感软件**。优先闲鱼销售，聚宽其次；目标是尽快发布并获得首笔真实软件收入，控制开发、托管和售后成本。

**首发完整度**：不能把“只有少量功能可以运行”的技术 MVP 当成最终商品。应能够直接和竞品3、竞品4比较完整的**发现→诊断→验证→跟踪**流程，包括手机上的体验及用户权益交付。

**不设 Alpha Gate**：不要求 S01–S08 先证明稳定赚钱、跑赢指数、收益显著或 WF 通过；不把用户访谈与竞品收入真实性验证设置为开发前置。软件规则、数据日期、历史计算、交易假设和用户权益必须准确，不能拿错误结果或模拟数据冒充真实能力。

### 3.1 F3 个股诊断：不做“详情页换名称”

诊断页面至少分成四个用户决策区：

1. **当前状态**：该股当前命中哪些模式；趋势、价格及成交量状态；市场和板块背景；盘中/盘后及计算时间。
2. **分项依据**：MA/相对强弱、量价、波动/流动性、板块及资金的实际数值和阈值。正面、负面、缺失证据并列，而不是只列支持看涨的指标。
3. **观察与失效**：适用的触发条件、风险位置、哪些变化使当前入选理由失效，分清“策略条件”与“个股当前状态”。
4. **可追溯历史**：能查看相同规则的历史信号、回测入口和关注后变化；不能把历史表现说成未来确定收益。

可采用分项标签或解释性评分增强可读性，但必须定义指标和算法版本。**筛选排名、诊断结论和买卖状态属于不同任务；出现分歧要解释原因，不得随意合成为预测胜率。**

### 3.2 盘中与盘后均可使用

用户随时打开应能看到**最近完成且有时间标记的有效结果**；交易时段允许刷新当前行情与规则暂态、盘后保存确认快照。最新缓存不等于已重新完成全市场扫描，应显示“扫描完成时间”和“行情数据时间”。具体自动更新周期由实际全市场数据能力决定，未经实测不承诺刷新秒数。

### 4.1 资金功能的竞争差距

已有留言中确有大资金/实时跟踪诉求，但现有 S08 明确是日频信号。对消费者应把两者分开：

- **已纳入首发**：日度主力净流入（沿用数据商字段名称）、近几日连续变化、S08 筛选、个股诊断中的资金分项，所有数据标注时间与来源口径。
- **尚未承诺**：逐分钟资金异动、盘中机构身份识别、真实委托追踪。若竞品对照证明这是首售不可缺的能力，需要另行评估数据与工程成本，再由 Owner 决定替换或增量，不用含糊的“实时资金”话术代替功能。

## 5. F6 回测：有商业竞争力、计算正确的基础能力

### 5.1 保留首发

- **B01/B02**：个股信号与历史 Top N 选股组合分开模拟。
- **B03**：真实发布的候选与后续表现单独保存，不补造历史发布。
- **B04–B06**：策略、时期、有限参数、初始资金、基准、交易成本及滑点；日线信号在完整收盘确认后、下一可交易时点尝试成交；涨跌停/停牌/交易单位及卖出限制要正确反映。
- **B07/B08**：净值、基准、回撤、累计及年化收益、最大回撤、夏普、胜率、盈亏比、交易次数及交易/持仓明细；不适用指标标记不适用。
- **B09/B10/B12**：保存结果及两组对比、简单分段、导出和清晰的运行/失败状态，不搭建通用研究任务平台。

### 5.2 首发暂缓但保留竞品差距记录

- **B11**：完整 Walk Forward；竞品3已有 WF 路径，但首发不需要把训练式参数选择系统作为必备。
- **B13**：用户可组合任意 AND 条件及其通用回测；先实现七套规则的有限参数控制。
- **B14/B15**：分钟历史回放、公式语言、任意 Python、自动参数优化。

**回测不是 Alpha 门禁，但回测商品功能必须真实。** 所有正式支持的回测需有可追溯的规则版本、数据时期、股票池及费用口径；不能用当前股票池重算过去，不以盘后回测冒充盘中触发收益；成交不可达时保留现金/仓位并说明原因。真实结果亏损也应原样显示。

## 6. 手机端：首发功能，而不是“以后做响应式”

### 6.1 建议的交付技术方案

优先比较并采用**同一套 Web 后端 + 响应式移动 Web 前端**，同时覆盖 PC 浏览器与 Android/iPhone 手机浏览器。理由：在不额外建设原生 App 代码、商店分发、双套账号/版本升级流程的情况下，让手机端从首发当天可用，较契合闲鱼成交发链接/邀请码的交付方式。

这只是**建议方案**，而不是已批准原生 App 不需要。用户若要求桌面图标、通知或手机安装体验，可评估 PWA；PWA 不能自动等同于原生应用或保证所有浏览器的后台推送。**不直接承诺 App Store 或安卓应用商店原生包。**

| 手机交付选项 | 首售吸引力 | 成本/限制 | 本次建议 |
|---|---|---|---|
| **移动 Web（响应式）** | 链接即用、无需安装，统一账号与策略结果 | 手机图表/表格需真正重新布局；依赖浏览器与网络 | **V0.1 主方案；完整手机体验属验收必需** |
| **PWA** | 可添加到主屏幕，接近轻量 App 入口 | 安装方式、离线及通知支持受浏览器/系统限制 | 可在不扩大后端时评估，不作为首发强制 |
| **Android/iOS 原生应用** | 独立应用外观、系统集成潜力 | 双端适配、发布分发、审核/签名及版本维护 | 仅在商品定位确需安装、原生通知或设备能力时另行批准 |

重要：**手机可用是已提出的产品要求；采用移动 Web 而非原生安装包仍是待 Owner 裁决的技术方案。**

### 6.2 手机验收用例

- 手机访问链接、登录/使用授权、到期提示都能独立完成。
- 单手操作可切策略、看 Top N、搜索、查看命中解释与分项诊断、加自选。
- 纵向手机屏可阅读 K 线、资金表和净值/回撤；图表缩放/横滑与触控不互相妨碍，重要数据不被宽表格截断。
- 能启动回测并查看核心结果、交易明细与异常状态；复杂参数可用折叠面板而不是照搬 PC 多列表单。
- 至少在典型 Android Chrome 和 iPhone Safari 上做真实设备或可复现的浏览器测试；具体系统支持范围在发布前确认。
- 慢网络/接口失败有进度和清晰提示，缓存不会装成最新扫描。

**交付衡量是手机能完成用户主链**，不是页面仅通过 CSS 缩小，也不把单独做 iOS/Android 客户端作为默认首发投入。

## 7. 上架及收费：形成完整商品闭环

建议首发采用**Web（PC+手机）+ 共享行情扫描/缓存 + 手工开通使用权**，单个服务与最小持久化，优先复用已有 `chstockdata` 可用能力，不建设统一平台、微服务、LLM/Agent 或分布式任务系统。

- 用户从闲鱼获得访问入口/兑换码，能试用、购买、开通、到期后看到权益状态，遇到问题能找到基础帮助。
- 优先设一个简单付费档期；卖家展示的 ¥29/月、¥199/年只是竞品参考，并非本产品已定价格。具体标价、试用期限仍须 Owner 确认。
- 不默认接在线支付、应用内购买、自动续费、桌面原生客户端或双端独立开发。

首售宣传必须与实际支持的平台、更新频率、回测区间、资金口径一致。不宣称必赢策略、可预测胜率或未经证实的盘中真实资金。

## 8. 开发前最小技术资格核查（不是金融研究）

**目的**：保证被 Owner 决定首发的功能能正确交付；不再争论选股是否具有 Alpha。

1. **S06**：行业分类及当前/历史成分能否支持扫描和同口径组合回测；来源、截止日期和缺口是什么。
2. **S08**：同供应商的日度净流入定义、单位、更新时刻、连续历史与证券覆盖，能否支撑扫描、诊断、回测；不把日频偷换成“盘中机构追踪”。
3. **F3**：七套策略的关键字段能否生成一致且可解释的分项诊断；哪几项必需字段现有 `chstockdata` 具备、哪几项无数据。
4. **F1/盘中**：全市场一次受控刷新时延、覆盖、数据时点与共享缓存方式；能否维持用户随时打开的产品要求。
5. **F6**：历史资格状态、交易限制、复权/单位、行情完整度能否达到标准日频回测合同；缺失时建议最小修正或明确 Owner 取舍。
6. **F8/手机**：同一 Web 应用在 PC 与 Android/iPhone 移动浏览器的可用性及 UX 实现成本；仅提出技术方案，不先建设两套客户端。

缺数据不是自动否决整个项目，也不允许“凑齐七套”造假；明确受影响能力、最小替代、成本和时长不确定性，交 Owner 裁决。无需再阅读594份资料、寻找 Alpha 或开展难以执行的客户访谈。

## 9. 上市前验收（软件与商品完成度，不是收益表现）

1. PC 和手机均能完成：进入→选股→个股诊断→加自选→回测→查看权益。
2. S01–S06、S08 七套规则能展示可复核候选和阈值；不把缺数据报成无机会。
3. S06 行业统计、S08 日度资金有来源及日期；各策略对外宣传的回测范围与数据真实能力一致。
4. 个股诊断包含足够的分项与正反理由，不能只是 K 线 + 一个分数；诊断与榜单各自任务语义一致。
